1 นำแอปขึ้นเว็บ (ใช้ deploy.bat เท่านั้น)

iPad เปิดไฟล์จากคอมโดยตรงไม่ได้ และแอปแบบติดตั้งบนหน้าจอโฮม (ใช้ออฟไลน์ได้) ต้องมาจากเว็บ HTTPS จึงต้องนำขึ้นเว็บก่อน ร้านนี้ใช้ GitHub Pages ที่ https://kiadtisakapi-eng.github.io/pos/

ครั้งแรกบนคอมเครื่องใหม่ (คอมเครื่องปัจจุบันตั้งไว้แล้ว ข้ามได้)

  1. ติดตั้ง Git for Windows และ Node.js (ใช้รันชุดทดสอบก่อนขึ้นเว็บ) แล้วปิด-เปิดหน้าต่างใหม่
  2. โฟลเดอร์โปรเจกต์ต้องเป็นสำเนาที่ clone มาจาก repo kiadtisakapi-eng/pos และล็อกอิน GitHub ในเครื่องแล้ว (push ได้)

ทุกครั้งที่จะนำรุ่นใหม่ขึ้นเว็บ

  1. ดับเบิลคลิก deploy.bat ในโฟลเดอร์โปรเจกต์ (มันเรียก deploy.ps1 ให้)
  2. สคริปต์จะ รันชุดทดสอบทั้งหมดก่อน — ถ้าขึ้น DEPLOY STOPPED แปลว่ามีเทสต์ไม่ผ่าน ห้ามหาทางข้าม ให้ส่งข้อความนั้นให้ผู้ดูแลระบบ
  3. ผ่านแล้วสคริปต์ส่งขึ้น GitHub ให้เอง · เพิ่มเลขรุ่นของแคช (jahn-pos-vN) และประทับวันที่ในเลขเวอร์ชัน เฉพาะเมื่อไฟล์ของแอปเปลี่ยน — แก้แค่เอกสาร/เทสต์/เครื่องมือ = เลขแคชเท่าเดิม iPad ไม่ขึ้นแถบอัปเดต (ไม่ต้องทำอะไรต่อ)
  4. จบด้วยข้อความ DEPLOYED -> https://kiadtisakapi-eng.github.io/pos/ และ cache version now: jahn-pos-vN — จดเลข N ไว้ (ถ้าขึ้น cache version unchanged = รอบนี้แก้แค่เอกสาร)
  5. รอ 1–2 นาทีให้ GitHub Pages อัปเดต
สิ่งที่ deploy.bat ไม่ทำ: ไม่อัปเดตโค้ด Apps Script — ถ้ารุ่นใหม่แก้ google_apps_script.js ด้วย ต้องวางเองตามขั้นที่ 2 (ทำ ก่อน deploy)
ไฟล์ใหม่ในโปรเจกต์: สคริปต์ส่งเฉพาะไฟล์ในรายการ $safeNewPaths ของ deploy.ps1 — ไฟล์นอกรายการจะถูกข้ามและขึ้นรายชื่อเตือนเป็นสีเหลือง นี่คือสิ่งที่กันไฟล์ส่วนตัวหลุดขึ้นเว็บ · แต่ถ้าแอปเรียกใช้ไฟล์นั้น (อยู่ใน index.html / sw.js / manifest.json) หรือเป็นไฟล์ข้อมูลใหม่ในโฟลเดอร์ tests/ tools/ vendor/ สคริปต์จะ DEPLOY STOPPED ทันทีโดยยังไม่ส่งอะไร — ส่งข้อความนั้นให้ผู้ดูแลระบบ

2 ต่อ Google Apps Script (Sheets + Drive)

ส่วนนี้ทำให้บิลและสรุปขึ้น Google Sheets และสำรองข้อมูลขึ้น Google Drive อัตโนมัติ

ตั้งครั้งแรก

  1. เปิด Google Sheets สร้างไฟล์ใหม่ 1 ไฟล์ (จะใช้เก็บข้อมูลทั้งหมด)
  2. เมนู Extensions → Apps Script
  3. ลบโค้ดตัวอย่าง แล้ว วางโค้ดทั้งหมด จากไฟล์ google_apps_script.js → กด บันทึก
  4. เลือกฟังก์ชัน setupPosApiToken ด้านบน → Run → อนุญาตสิทธิ์ → คัดลอก รหัสเชื่อมต่อ จาก Execution log
  5. เลือกฟังก์ชัน setupPosOwnerKey → Run → คัดลอก Owner key (หน้าตา XXXX-XXXX-XXXX-XXXX-XXXX) จาก Execution log
    จด Owner key เก็บไว้กับเจ้าของร้านเท่านั้น (กระดาษ/ที่เก็บรหัสส่วนตัว) — ไม่ต้องใส่ไว้ในเครื่องไหน แอปจะถามตอนใช้
    ไม่มีรหัสนี้ = กู้ข้อมูลจาก Drive ไม่ได้ · ตั้งเครื่องหลักใหม่ไม่ได้ · ตรวจความตรงกันกับชีตไม่ได้
  6. กด Deploy → New deployment → รูปเฟือง ⚙️ ข้าง "Select type" → Web app
  7. ตั้งค่าให้ตรงนี้ เป๊ะ ๆ:
    ช่องตั้งเป็น
    Execute asMe (อีเมลคุณ)
    Who has accessAnyone
  8. กด Deploy → Authorize → เลือกบัญชี → "Advanced" → "Go to (project) (unsafe)" → Allow ทำครั้งเดียว
  9. คัดลอก Web app URL (ลงท้าย /exec) เก็บไว้คู่กับรหัสเชื่อมต่อ ใช้ในขั้นที่ 4

อัปเดตโค้ด Apps Script (รุ่นใหม่ที่แก้ไฟล์นี้)

  1. Extensions → Apps Script → ลบโค้ดเดิมทั้งหมด → วาง google_apps_script.js ตัวใหม่ → บันทึก
  2. Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy — ไม่ทำขั้นนี้ ของเก่าจะยังทำงานอยู่ (URL เดิมใช้ต่อได้ ไม่ต้องแก้ในแอป)
  3. ถ้ายังไม่เคยตั้ง Owner key ให้รัน setupPosOwnerKey แล้วจดรหัส (ถ้าตั้งไว้แล้ว log จะขึ้นว่า "ตั้งรหัสเจ้าของไว้แล้ว" และไม่เปลี่ยนอะไร)
ห้ามรัน rotatePosApiToken — อยู่ติดกับ setupPosApiToken ในเมนูเลือกฟังก์ชัน กดพลาดง่าย มันสร้างรหัสเชื่อมต่อใหม่ทับทันที ทุกเครื่องที่ถือรหัสเก่าหลุดการเชื่อมต่อหมด (บิลไม่ขึ้นชีต · สำรองขึ้น Drive ไม่ได้)
setupPosApiToken ปลอดภัย รันซ้ำได้ — ถ้ามีรหัสอยู่แล้วจะแสดงรหัสเดิม ใช้ "ดูรหัสที่ถูกต้อง" ได้เสมอ
ลืม Owner key: รัน rotatePosOwnerKey ได้ — ได้รหัสใหม่ รหัสเก่าใช้ไม่ได้ทันที ไม่กระทบการขาย/สำรองอัตโนมัติ (คนละตัวกับ rotatePosApiToken)
ชีตที่ระบบสร้างให้เอง: สรุปรายเดือน (ตารางรวม), MM-yyyy (รายการบิล — เก็บถาวร), สรุป-MM-yyyy (เก็บถาวร) และ สรุป-YYYY-MM-DD (สรุปรายวัน — ลบเองเมื่อเกิน 62 วัน) — ไม่ต้องสร้างเอง

3 ติดตั้งบน iPad (เพิ่มลงหน้าจอโฮม)

  1. บน iPad เปิด https://kiadtisakapi-eng.github.io/pos/ ด้วย Safari
    สำคัญ: ต้องเป็น Safari เท่านั้น — Chrome บน iPad ติดตั้งแบบเต็มจอ/ออฟไลน์ไม่ได้
  2. แตะปุ่ม แชร์ ⬆️ สี่เหลี่ยมมีลูกศรขึ้น → "เพิ่มไปยังหน้าจอโฮม" (Add to Home Screen) → ตั้งชื่อ → เพิ่ม
  3. เปิดแอปจากไอคอนบนหน้าจอโฮมเสมอ (ไม่ใช่เปิดผ่าน Safari) — iOS จะถือว่าเป็นแอปที่ใช้งานอยู่ และไม่ล้างข้อมูลทิ้ง
ครั้งแรกต้องต่ออินเทอร์เน็ต เพื่อโหลดไฟล์เก็บไว้ในเครื่อง หลังจากนั้นขายแบบออฟไลน์ได้
เครื่องหลัก — ต้องเปิด iPad ร้านก่อนเครื่องอื่น: Apps Script รับสรุปวัน/เดือนและไฟล์สำรองจาก "เครื่องหลัก" เครื่องเดียว และถือว่า เครื่องแรกที่ส่งสรุปหรือไฟล์สำรองขึ้นไป คือเครื่องหลัก ถ้าคอมที่ใส่ URL+รหัสไว้ส่งก่อน iPad ร้านจะสำรองขึ้น Drive ไม่ได้
แก้ได้: iPad ร้าน → หน้าตั้งค่า → บรรทัด "เครื่องนี้" → ปุ่ม ตั้งเครื่องนี้เป็นเครื่องหลัก (ต้องใช้ Owner key)

ข้อมูลร้านเก็บอยู่ใน iPad เครื่องนั้น: iOS อาจล้างข้อมูลเว็บถ้าไม่ได้เปิดแอปนานหลายสัปดาห์ หรือพื้นที่เครื่องเต็ม — ระบบจึงสำรองไว้ 3 ชั้น
  1. บิลทุกใบขึ้น Google Sheets อัตโนมัติ เมื่อใส่ URL + รหัสเชื่อมต่อครบ (ออฟไลน์อยู่ = ค้างไว้ ส่งเองเมื่อเน็ตกลับมา)
  2. ไฟล์สำรองขึ้น Google Drive อัตโนมัติ ทุกครั้งที่ปิดกะ ระหว่างกะทุก 5 บิล และราว 2 นาทีหลังยกเลิก/แก้บิล (เฉพาะเครื่องหลัก) · Apps Script เก็บย้อนหลัง 90 วัน แล้วลบไฟล์ที่เก่ากว่านั้นเอง แต่เก็บ ไฟล์ล่าสุดอย่างน้อย 10 ไฟล์ไว้เสมอ — ไม่ต้องเข้าไปจัดระเบียบใน Drive เอง · ดึงกลับได้จากปุ่ม "กู้ข้อมูลจาก Google Drive" ในหน้าตั้งค่า (ต้องใช้ Owner key · ไฟล์ล่าสุดอยู่บนสุด แสดงครั้งละ 200 ไฟล์ กด "โหลดไฟล์เก่าเพิ่ม" เพื่อย้อนไกลกว่านั้น — หรือดาวน์โหลดจาก Drive แล้วใช้ปุ่มนำเข้า)
  3. ส่งออกไฟล์ .json เก็บเอง เป็นระยะ (เช่น สัปดาห์ละครั้ง): หน้าตั้งค่า → ส่งออกข้อมูลสำรอง (.json) → บน iPad จะเปิดเมนูแชร์ → ส่งไปเครื่องหรือบัญชีของเจ้าของร้านเอง (เช่น AirDrop ไปมือถือเจ้าของ · อีเมลถึงตัวเอง · iCloud Drive ของบัญชีเจ้าของ — ไม่ใช่บัญชีที่ใช้ร่วมกันในร้าน) → แอปขึ้นข้อความบอกผล → ตรวจว่าไฟล์ถึงเครื่องเจ้าของจริง · ถ้ากดยกเลิกเมนูแชร์ แอปจะบอกว่ายังไม่ได้บันทึก
    ⚠️ ไฟล์นี้มีประวัติทั้งร้าน (บิล ลูกค้า ค่าคอม ต้นทุน ทุกวันตั้งแต่เปิดร้าน) — ถ้าเลือก "บันทึกไปยังไฟล์" ไว้ใน iPad ร้าน ให้ย้ายไปเครื่องเจ้าของแล้วลบออกจากแอป "ไฟล์" ของ iPad ร้าน (ผู้จัดการ/พนักงานที่ใช้ iPad เปิดอ่านได้)
