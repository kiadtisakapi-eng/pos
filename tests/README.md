# ชุดทดสอบ (ใช้ Node อย่างเดียว ไม่ต้องติดตั้งอะไรเพิ่ม)

```bash
node tests/run-all.js     # รันทั้งหมด — ใช้ก่อน deploy ทุกครั้ง
```

| ไฟล์ | ทดสอบอะไร |
|---|---|
| `test_app.js` | นำเข้า/กู้ข้อมูลจาก Drive |
| `test_gas.js` | คอลัมน์ในชีต + ความปลอดภัยไฟล์สำรอง |
| `test_shift_variance.js` | เงินขาด/เกินตอนปิดกะ ตั้งแต่แอปถึงชีต |
| `test_update_flow.js` | กลไกอัปเวอร์ชัน Service Worker |
| `test_vat.js` | VAT รายกลุ่ม + ปัดเศษขึ้นเต็มบาท |
| `test_roles.js` | สิทธิ์ตามตำแหน่ง + ประวัติบิลที่ยกเลิก/ค่าใช้จ่ายที่ถูกลบ |
| `test_core.js` | แกนกลางที่ไม่มีใครตรวจมาก่อน: เซฟ/โหลด, นับเงิน, PIN+ล็อกอิน, ปัดเศษ, ซิงก์ |

`harness.js` = DOM/Dexie/localStorage ปลอม ไว้โหลด `app.js` มารันใน Node
ไม่แตะข้อมูลจริงในเครื่อง และไม่ยิงเน็ตออกไปไหน


## ⚠️ กับดักของชุดเทสต์นี้: `app` เป็นตัวเดียวกันทั้งไฟล์

ทุกไฟล์โหลด `harness.js` แล้วได้ `app` **ตัวเดียว** ใช้ร่วมกันตั้งแต่ต้นจนจบไฟล์
เทสต์ท่อนบนที่เขียนทับเมธอดไว้ (`app.flushCloudOutbox = () => {}`) จะยังทับอยู่ตอนเทสต์ท่อนล่างรัน
→ เทสต์ท่อนล่างเรียก "ตัวปลอม" โดยไม่รู้ตัว แล้วขึ้น PASS ทั้งที่ยังไม่ได้ตรวจอะไรจริง

**โดนมาแล้ว 2 ครั้ง (ส.ค. 2569)** กับ `flushCloudOutbox` และ `loadDriveBackups`

**ถ้าต้องเรียกตัวจริงหลังมีคนอื่น stub ไปแล้ว:**
```js
const real = Object.getPrototypeOf(app).ชื่อเมธอด.bind(app);
```

**และอย่าลืม:** `t()` ใน `test_edge.js` / `test_roles.js` เป็นแบบ sync
ถ้าส่งฟังก์ชัน `async` เข้าไปจะขึ้น PASS ทันทีโดยไม่ตรวจอะไรเลย (มีตัวดักให้ FAIL แล้ว)
วิธีที่ถูกคือ `await` ผลไว้ข้างนอกก่อน แล้วค่อยส่งค่าที่ได้เข้า `t()`

**บทเรียนรวม:** เทสต์ที่เรียกฟังก์ชันตรง ๆ ผ่านได้ ไม่ได้แปลว่าทางที่ผู้ใช้เดินจริงจะผ่านด้วย
เรื่องที่กระทบสิ่งที่ผู้ใช้เห็น ให้เทสต์ผ่านทางจริงเสมอ (เช่นยิง `loadDriveBackups`
แล้วอ่าน `innerHTML` ที่ขึ้นจอ แทนการเรียก `explainCloudError` ตรง ๆ อย่างเดียว)

## เทสต์หน้าจอ (เพิ่ม ส.ค. 2569)

`run-all.js` = ด่านก่อน deploy — เทสต์ตรรกะล้วน ไม่ต้องลงอะไรเพิ่ม เร็ว
`run-all-ui.js` = เทสต์หน้าจอ เปิดเบราว์เซอร์จริง ใช้เวลาหลายนาที **รันเองเมื่อแก้ CSS**

```
npm i -D playwright          # ครั้งแรกครั้งเดียว
node tests/run-all-ui.js     # ตรวจหน้าจอทั้งชุด
SHOT=pos node tests/responsive.js   # ถ่ายภาพทุกขนาดลงโฟลเดอร์ shots/
node tests/density.js        # ดูความกว้างการ์ด/จำนวนบรรทัดชื่อบริการ
```

ไฟล์ในชุดหน้าจอ:
- `browsertest.js` — ต้องไม่มีคำขอวิ่งออกนอกเครื่อง และไอคอนต้องขึ้นจริง
- `offlinetest.js` — ตัดเน็ตแล้วเปิดใหม่ ไอคอนกับฟอนต์ไทยต้องยังขึ้น
- `responsive.js` — 13 ขนาดหน้าจอ x 6 หน้า คอลัมน์ "ล้นแนวนอน" ต้องว่างหมด
- `modaltest.js` — 7 หน้าต่างป๊อปอัป x 6 ขนาด ต้องกดปุ่มยืนยันถึงทุกช่อง
- `uiguard.js` — กันบั๊กเก่ากลับมา (ล็อกอินซ้อนใต้หน้าต่าง / ใบเสร็จถูกตัดตอนพิมพ์)
- `e2e_boot.js` — ช่วงเปิดแอป (init/Service Worker/ธีม) + ปุ่มแจ้งเตือน อัปเดต ล็อก
- `e2e_browser.js` — เดินทั้งวันของร้านด้วยการกดจริง: ล็อกอิน → เปิดกะ → ขาย → ค่าใช้จ่าย → ยกเลิกบิล → ปิดกะ
- `e2e_settings.js` — หลังร้าน: บริการ/หมวด/พนักงาน, **QR พร้อมเพย์**, สำรอง→นำเข้าข้อมูล, ธีม, โลโก้
- `seed.js` / `density.js` — ตัวช่วย ไม่ใช่เทสต์ผ่าน/ไม่ผ่าน
